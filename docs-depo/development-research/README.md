# development-research

Research notes written while deciding how to build CRAFT. Service evaluations, architecture spikes, security/compliance investigations — anything that informed a build decision but didn't itself ship as code.

Each entry is a single markdown file named after its topic. Cite sources (vendor docs, standards, internal interviews with dates) at the bottom of each file. Mark entries as superseded rather than deleting them when a decision changes — the trail is the point.

For scouting third-party open-source tools and dependencies, use `../exploration/` instead.
